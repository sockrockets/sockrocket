# 性能优化复查与路由器部署（2026-11-03）

对[前四项实现](performance-optimization-implementation-2026-11-03.md)进行复查，未发现阻止本次核心部署的问题。本次没有追加运行时实现修改；补充了连接池真实 TLS 回归测试，然后从固定源码快照构建并部署到用户的 RT-AX86U Pro。

## 合理性与验证边界

- **统计归并**：增量桶的节点、订阅及 UTC 日归属固定；切换归属时旧桶先归并，快照/保存/释放会处理剩余增量。后台归并与 recorder 释放通过注册表串行化，检查了锁顺序、取消、并发 drain 和保存失败重试。实时全局与连接计数仍独立更新。
- **连接池**：预热上限与前台连接分开，额度覆盖后台握手；公开句柄释放会取消后台工作。较少初始预热和 30 秒闲置年龄有明确的冷突发延迟取舍，不将它们宣称为所有场景必然更快。
- **复用前读检查**：新增内存传输上的真实 TLS 1.3 互操作测试，使用生产 craftls connector 与独立 rustls server，确认 post-handshake session ticket 不会使预热连接被误判失效，随后 ping/pong 数据完整。连接池测试共 10 项通过。一次非阻塞读仍无法证明网络不存在静默失效。
- **缓冲**：只降低低内存设备普通 relay 的拷贝缓冲；当前约 1 GiB 设备仍使用每方向 64 KiB，TUN 保持每方向 16 KiB，未降低既有 TCP 窗口及修改网络 MTU 策略。
- **桌面列表**：内容与测速顺序分别失效，保留原先匹配与排序语义；索引映射保持重复名称节点的身份。此部分不进入路由器 CLI。

此前 core/CLI 774 项、桌面逻辑 9 项及新增保存失败重试测试的成功结果仍适用于运行时实现。复查阶段只增加上述 TLS 回归；没有将忽略的真实节点测试计为通过。

比对最近部署源码清单，已有的 MTU 配置 watcher 改动也被核对：它使 `tun_mtu` 变化被识别为需要重启，与现有 MTU 功能一致。原有协议功能保留。

## 部署与验收

先验证旧服务和 DNS/SOCKS/TUN，再把候选上传至 tmpfs，核对哈希与 `--check-config` 结果。替换前保留旧程序，并启动独立 watchdog 与失败回滚处理。停止 daemon/API 后只替换可执行文件，随后重启并验证两个进程的实际 `/proc/.../exe` 哈希。

结果：

| 检查 | 结果 |
| --- | --- |
| daemon 与 API | 均运行候选哈希；后续检查 daemon PID 保持一致 |
| DNS 53 / 5300 | 健康检查通过 |
| API / 防火墙 | 通过 |
| 路由器 SOCKS HTTPS | 204 |
| 实际 TUN HTTPS | 204 |
| LAN DNS / LAN SOCKS HTTPS | 通过 / 204 |
| TUN 下载 | HTTP 200，1,048,576 字节，2.809 秒 |
| 配置、启动/防火墙脚本、版本文件 | 与部署前 SHA256 一致 |
| 磁盘空间 | JFFS 约 60% 使用，无残留替换文件 |

新进程完成下载后的 RSS 约 25.3 MiB。部署前长时间运行进程的 RSS 约 38 MiB；重启会改变累计状态，不能把该差异全归因于优化。单次网络测试也不构成吞吐加速结论，长期 RSS 与首字节分位数尚需持续观察。

部署后已将旧程序与配置备份下载到本地私有归档并核验 SHA256，路由器也保留旧程序。删除了本次上传的临时候选副本，释放 tmpfs 占用；匹配符号和回滚备份继续保留。
