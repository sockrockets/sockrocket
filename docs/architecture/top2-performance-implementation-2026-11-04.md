# Vision 预连接与 TUN 下行优化

日期：2026-11-04。实现已完成，并已部署到 RT-AX86U Pro，通过访问和并发下载检查。

## Vision 预连接

- 将连接池泛化为保留具体流类型的池，普通出站继续使用默认 `BoxProxyStream`。
- Vision 的 TCP 和 XUDP 建连共用具体 TLS 流的池；只预先完成原有 TCP/TLS/REALITY 握手，不提前发送目标地址或业务数据，不复用已经使用过的连接。
- 每个 Vision 池最多两条预连接，和普通池共享全局预热预算；沿用 30 秒过期、取出时检查关闭/异常数据、无需求不持续补充及释放最后一个句柄时取消维护任务的机制。
- `warm_pool` 从工厂传入 Vision，测速探针不启动后台预连接。原有 TLS 1.3 校验和 REALITY 握手策略保留。
- 预期改善池命中的新连接等待时间；不代表持续下载吞吐提高。新增加的 sing-box 互通测试覆盖原生 TLS，尚未对实际 REALITY 节点做优化前后测速。

## TUN 下行

- 每次 `poll_write` 最多发送 16 段或 16 KiB；同一轮共用一次 TCB 锁，并合并超时更新及重传任务通知。
- 每段重新检查 MSS、MTU、可用窗口、单流及全局字节预算。队列满或预算不足时返回已接受前缀；未接受任何字节时保留 Pending/错误语义。
- 发送队列和重传队列共享 `Bytes`，正常新发送由两次 payload 复制降为一次。每个分段单独分配，避免小段 ACK 尾部保留整块批量缓冲。
- 部分 ACK 仍将剩余尾部复制到更小的分配中，再返还已确认字节的信用。入站使用拥有所有权的 Vec，交给 TCP 重组、UDP 或未知协议时直接移动，保持原来的无额外复制路径。
- 数据队列原有计费和 ACK/DNS 预留不变；没有合并 TUN IP 包或改变设备写入方式。
