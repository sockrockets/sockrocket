# Merlin 发布与接管验证方案

目标：先验证路由器，再切换桌面流量；节点、订阅、凭据和设备地址只留在忽略的本地配置与私有备份中。

| 阶段 | 检查 | 通过条件与失败处理 |
| --- | --- | --- |
| 离线回归 | 核心、CLI、脚本故障场景、RPC、WebUI | 全部必需检查通过；失败先修复，不部署未验证产物 |
| 安全部署 | 私有备份、配置比对、文件摘要、API 鉴权 | 不覆盖订阅及节点；部署失败恢复运行文件 |
| 代理出站 | LAN HTTP CONNECT / SOCKS，国内与国际站点 | 百度 HTTPS 成功、Google 连通检测成功；不把 SOCKS 成功等同透明转发成功 |
| DNS | LAN UDP / TCP 53，真实响应；接管上游 5300 | 正常响应、无超时、配置可被降权 dnsmasq 读取；失败立即恢复直接上游 |
| 生命周期 | 多轮服务停止与启动 | 停止无专用路由、NAT、上游 pin 与 Fake-IP 残留，配置持久保存；启动后重复验证数据面 |
| 故障恢复 | 受控退出代理主进程，观察监督恢复 | 管理面可达；失败时释放接管、恢复直连；恢复后重新通过数据面验证 |
| 性能与观察 | 有界并发与连续采样 | 无持续资源增长、无进程重复启动；记录实际观察时长，短测不替代长期验收 |
| 整机重启 | 仅获得允许后执行 | SSH、管理页、DNS与代理按用户运行意图恢复，不要求重新导入订阅 |
| 客户端接管 | 路由器前置检查通过后停止本地代理 | 清除本应用本地系统代理/TUN；物理默认路由恢复；无需本地代理的百度/Google实际访问成功 |

不能把本机 TUN 的成功、节点延迟成功或路由器自身 SOCKS 成功当作 LAN 透明代理通过。接管后的纯 LAN 验证是独立门槛；失败立即停止继续切换并恢复可用路径。

退出清理应恢复本软件拥有的变更，保留用户原有网络设置。缓存清理不删除持久化订阅与节点。所有共享诊断只保留状态、错误类别和聚合指标，避免原始配置与请求凭据。
