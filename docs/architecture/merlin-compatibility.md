# Merlin compatibility notes

This is the current implementation boundary, not a claim that every Asus router or network has been tested. Firmware behavior is based on the [official user-script reference](https://github.com/RMerl/asuswrt-merlin.ng/wiki/User-scripts), [supported-model README](https://github.com/RMerl/asuswrt-merlin.ng/blob/main/README-merlin.txt), and [3006 changelog](https://github.com/RMerl/asuswrt-merlin.ng/blob/main/Changelog-3006.txt). KoolCenter forks and individual devices still need router testing.

| Area | Current handling | Boundary / validation needed |
| --- | --- | --- |
| Firmware and CPU | Installer selects ARMv7 or AArch64, validates that the bundled binary executes, and installs the package's scripts. | Platform tags and model lists in [the install guide](../merlin.md) are package mappings, not proof of runtime support on every firmware fork. Old 384/386 builds may lack current kernel or userspace facilities. |
| JFFS hooks | Full install checks an explicitly disabled `jffs2_scripts` switch. `wan-event`, legacy `wan-start`, `firewall-start`, `nat-start`, and DHCP events restore owned state. | JFFS custom scripts must be enabled. A stripped installer environment may not expose `nvram`; verify the setting on the router. `--update` changes only the binary, so use full install for hook changes. |
| WAN | WAN connection and firewall events restore Sockrocket's private policy table 5370 and DNS without selecting a physical interface by name. This covers the same code path for DHCP, static WAN, and PPPoE. | Dual-WAN failover and load-balancing need tests on each firmware line; firmware event order and ISP reachability can differ. A `connected` event is not proof that the Internet is reachable. |
| IPv4 LAN | Transparent and DNS rules use the validated primary `lan_ipaddr` / `lan_netmask` subnet **and** the `lan_ifname` bridge (default `br0`). Missing or malformed NVRAM values disable interception rather than selecting a guessed subnet; Stop can still remove owned rules. On Merlin 3006, `dnsmasq.postconf` removes `servers-file` and `resolv-file` from the main DNS config and inserts `server=127.0.0.1#port`. The shared `/tmp/resolv.dnsmasq` remains available to SDNs. A missing postconf hook fails open. | Additional LAN bridges/VLANs and Merlin 3006 Guest Network Pro / SDN networks are **not** currently included in transparent interception. SDN dnsmasq instances and routes are separate; applying main-LAN rules to all bridges would change guest isolation and needs explicit design and router validation. |
| IPv6 | Compatibility mode preserves IPv4 proxying. Optional dual-stack reads the main LAN interface/prefix; DHCPv6 `bound`, `unbound`, `stopped`, `updated`, `rebound`, `informed`, and `ra-updated` events now retry IPv6 policy and DNS independently. The watchdog retries if the prefix is not ready when the event arrives. | Dual-stack depends on firmware IPv6 and a LAN prefix. IPv6 on extra LAN/SDN interfaces, delegated prefixes per network, and IPv6-only WAN are not established as supported. Validate on real equipment before enabling dual-stack broadly. |

The official script reference says `dhcpc-event` receives event type and IP version (`4` or `6`), while `wan-event` reports WAN unit and event. It also lists the IPv6 prefix and RA update events. These details are why the hook dispatch uses both DHCP arguments and keeps WAN recovery interface-independent.

The 3006 firmware [generates each SDN dnsmasq configuration separately](https://github.com/RMerl/asuswrt-merlin.ng/blob/main/release/src/router/rc/sdn.c), and a default SDN instance can use the same `dmservers` path as the [main dnsmasq instance](https://github.com/RMerl/asuswrt-merlin.ng/blob/main/release/src/router/rc/services.c). The main config no longer reads the shared resolv, so Fake-IP DNS answers stay off SDNs that have no Sockrocket forwarding policy. Existing installations need a **full install**, not binary-only `--update`, to add the `dnsmasq.postconf` hook; the runtime refuses to enable 3006 DNS interception when that hook is absent.

For device acceptance, test one device from each **actual** firmware/CPU family in use: first install with JFFS hooks enabled, cold boot, DHCP lease renew, PPPoE or static-WAN reconnect where applicable, dual-WAN failover if configured, firewall/NAT rebuild, DNS listener failure and recovery, then IPv6 prefix renewal in dual-stack mode. Check that manual Stop and fail-open never re-enable interception, that the main LAN still resolves DNS, and that guest/SDN networks retain their intended isolation. Local integration tests exercise hook dispatch and state transitions but cannot prove firmware event timing, kernel modules, or guest-network topology.
