## 百度故障证据

2026-10-16 现场检查：旧桌面版的默认路由为 utun4，物理 en1 没有 scoped default；绑定 en1 的 curl 返回 Network is unreachable。路由器当时手动停止透明代理，路由器自身访问百度成功。这证明本机 TUN 的物理出口有确定故障，但不能据此宣称先前路由器接管时的全部故障都已归因。

候选代码已补 IPv4 scoped 路由。当前 `sudo -n` 返回需要密码，尚未修改运行中的系统路由，也未验证修复后现场请求。需管理员授权后应用并复测。

## 仍需处理/验收

- macOS IPv6 scoped 出口及部分失败回滚需与 IPv4 对齐；已有 /32、/128 旁路路由的所有权需完整记录，避免退出时删除预先存在的路由。当前 scoped IPv4 所有权已记录，其余路由仍沿用原清理逻辑。
- 路由器真实环境：CGI/KSC 依赖固件会话认证，新 WebUI 传输尚需登录态验收；真实节点 UDP 互通、百度及 LAN DNS 接管/降级/停止恢复未验收。
- 256/512 MiB 真机持续负载及 WAN 重连尚未实测；资源预算测试不能替代硬件压力测试。
- ShadowTLS 不支持 UDP，能力显式返回 false；VMess 原生 UDP 单报文受 AEAD chunk 上限约束，空数据报及超限报文明确报错，不拆成多个包。未新增 Reality/Vision/XUDP 扩展。
- GUI 状态/副作用及 TUN 平台路由仍需继续拆分，不能称为全部架构工作完成。
