# 性能与发布体积优化评估（2026-11-03）

后续前四项体验优化的落地与验证见[实现记录](performance-optimization-implementation-2026-11-03.md)。以下保留实施前评估。

本次基于当前工作区源码、离线 Cargo 依赖图和已有本地产物进行评估。工作区包含未提交的协议改动；本文不修改实现，也没有重新构建、部署、运行吞吐基准或修改在线配置。以下区分已确认的实现事实与待测的收益。

## 优先结论

优先做两项独立实验：流量账本退出逐次 I/O 热路径，以及收窄现代 TLS 依赖的默认 features。其次测量连接池预热策略、桌面 relay 缓冲和字体资产。双 TLS 栈合并、协议裁剪、PGO 放在后面；它们涉及较大的兼容性或维护成本。

当前已经有 thin LTO、单 codegen unit、符号剥离、reqwest 禁用默认功能、连接准入、TUN 内存预算、日志缓存和静态页面避免心跳重绘。这些不能再作为“尚未实施”的优化收益重复计算。

gzip 数值是对已有单个可执行文件进行内存压缩得到，既不是实际 DMG/ZIP/tar.gz 大小，也不影响运行时内存。磁盘体积、下载体积、代码驻留、堆内存、构建缓存应分别度量。

## 1. CPU 与分配：优先降低统计成本

依据：`proxy/mod.rs` 的 `ObservedIo::poll_read/poll_write` → `ProxyStats::add_bytes` → `traffic.rs` 的 `record_parts`。

当前每次有效 I/O 在原子计数之外，还可能访问账本锁、任务局部目标、session/history/subscriptions 锁，以及名称处理、字符串构造和 `month_key()`。尤其在高吞吐、小分块、多连接时，这些工作可能放大；尚无 CPU profile 证明占比。

建议：

- 全局和连接实时字节保留原子累加；在连接或节点计数器中聚合账本增量，以周期或字节阈值批量归并。
- 在连接建立时保存稳定的节点/订阅标识，避免逐块复制身份和名称。
- 归并时更新月份桶，明确跨月边界；连接结束、取消和正常退出时排空尚未归并的增量。
- 避免为每块数据向 channel 发一条消息，否则只是把锁成本换成分配与调度成本。

验证：同一协议分别测启用/禁用账本、单连接/多连接、大块/小块传输的 CPU/GiB 和分配次数。计数验收必须覆盖取消、节点切换、订阅归属、跨月、持久化失败及重复归并。周期归并会增加内存账本可见延迟，必须单独规定；当前磁盘持久化本来已有 60 秒间隔。

## 2. 首连与空闲成本：连接池自适应

依据：`proxy/pool.rs`，以及 VLESS、VMess、Trojan、ShadowTLS 的池构造。

容量 16 是每个实际池的容量。可以对低内存设备实验 2/4/8/16 的分档策略：初始少量预热，持续消费后增长，长时间无消费时收缩，并给所有活跃池设置总预热额度。池填充任务还应验证切换节点或停服务后的生命周期，避免后台填充延长旧出站的存活。

120 秒只是本地年龄判断，不能证明对端仍接受闲置连接。应记录复用成功率、取出后首写失败和握手重试；调短年龄会增加握手负载。失败后的自动重试只能用于尚未发送不可安全重放数据的阶段。

验证：冷启动、空闲数分钟后的首次访问、突发 32/128 条连接、频繁节点切换。同时比较首字节 P50/P95、握手次数、空闲 RSS 和复用失败率。

## 3. 吞吐与并发内存：按路径调缓冲

普通 relay 双向合计 128 KiB，512 条对应 64 MiB 缓冲容量；TUN 双向合计 32 KiB，同样数量对应 16 MiB。实际分配与驻留需要测量。

先实验普通 relay 每方向 16/32/64 KiB，并按设备预算选择，而不是统一降低所有 TCP 窗口。relay 拷贝缓冲、用户态 TCP 接收窗口、在途数据和内核 socket 缓冲属于不同层：TCP 窗口还受带宽时延积影响。资源预算已存在，应在其上调整，保留 DNS/控制面余量。

验证：近端高速、远端高 RTT、慢消费者、上传下载并行和数百条空闲连接。必须保留 half-close、反向长响应、背压和取消语义。若吞吐受加密或上游限制，增大缓冲未必有效。

## 4. 运行内存：区分存活对象与分配器保留

项目已有 Zig 最终链接导致分配器保留的历史诊断，以及 `build-merlin-musl.sh` / `verify-merlin-allocator.py`。继续把最终 malloc/free 来源验证作为本地产物检查项；不要仅凭 RSS 高就判定 Rust 对象泄漏，也不能把历史现场结论当作当前产物的测量。

同一 PID 记录请求存活字节、连接/队列数量、RSS/匿名 RSS、峰值、空闲恢复曲线。重点测反复订阅刷新、测速、切换节点和连接突发后的稳态。队列预算不能作为整个进程 RSS 上限。

## 5. 可执行体积：先收窄加密 features

根 manifest 对现代 rustls 添加 `ring` 时仍保留默认功能；现代 tokio-rustls 也使用默认功能。实际 feature 图显示它们启用了 aws-lc，以及 rustls 默认的后量子偏好。添加 ring 并不会自动关闭默认后端。

优先在独立候选中关闭这两处默认功能，显式保留实际需要的 ring/std/TLS 1.2/日志功能，再检查整张图是否还有 aws-lc 来源。对 quinn 的 platform-verifier 等默认功能也先核对调用点再裁剪。

这可能减少编译和链接成本，最终体积收益需重建量化。移除 aws-lc 还可能改变现代 TLS 的后量子能力，必须检查实际 provider 与 key exchange 需求，不能当作纯粹删除重复代码。自定义 craftls 的 ML-KEM 是另一条实现路径，不能混为一谈。

两代 TLS 暂不强行合并：`proxy/transport.rs` 使用 craftls 的 ClientHello 指纹与 REALITY 扩展，现代依赖则支撑 reqwest/QUIC 等路径。统一需要移植和完整协议回归，不是改版本号即可完成。

craftls 的 brotli/zlib/zstd 用于证书压缩。可研究客户端裁剪与编码器/解码器分离，但需保留所宣告算法的实际支持及指纹一致性。不能仅从依赖大小推断可删。

## 6. 产品功能与 GUI 资产

核心依赖当前无协议级 optional feature 划分。中期可增加 full 与受限设备配置，将确实可选的协议、TUN、管理功能及其依赖完整 gate。先保留完整默认包；精简包必须在配置校验阶段明确拒绝未编译功能，导入/导出和界面也要同步。

不能只删除依赖但保留工厂分支，也不能在没有用户需求证据时默认裁掉 WireGuard、QUIC 或浏览器指纹。

GUI 的字体可比较：实际使用字重子集、字体字符子集、可变字体、系统字体回退。要验证中英越文本、重音字符、数字对齐、粗体效果和许可证。保留全部字体与更少字体进行截图及启动耗时对照；可变字体未必比当前组合更小。

日志已有按 generation 和过滤条件的缓存，静态页面已有避免定时重绘逻辑。GUI 后续重点测大节点列表和筛选/排序的 UI 线程耗时，按测量决定可见行渲染、增量更新或后台解析。

## 7. 规则与 DNS：以缓存未命中场景评估

路由已有 4096 项 LRU。规则未命中缓存时仍按序扫描；大量规则或大量唯一域名可以实验域名后缀索引、精确匹配索引和 CIDR 索引。

任何索引必须保留原先优先级、稳定顺序、source/port 条件与 DNS 延迟解析语义，不能让“精确匹配更快”改变匹配结果。首先测 100/1,000/10,000 条规则、冷热缓存与高基数域名，再决定是否值得引入索引复杂度。

## 8. 编译参数与分发

已有 thin LTO、codegen-units=1、strip=symbols。新增实验 profile 对比 opt-level 3/2/s/z、thin/fat LTO，逐个变量验证原始体积、压缩体积和吞吐。`z` 关闭循环向量化，且 `s/z` 不保证一定更小，不能直接全局替换。

根 manifest 的“不设 panic=abort，因为测试依赖 unwind”注释不够准确：Cargo 测试框架会忽略此设置并以 unwind 构建。可单独实验发布 profile 的 abort；但真实发布程序的 panic 会立即终止，RAII 清理与任务 panic 隔离行为会变化。需要验证代理恢复、guardian、流量落盘和进程退出，普通单元测试通过不能证明 abort 产物可安全发布。

PGO 放在稳定、可重放的流量样本之后；训练应覆盖实际常用协议与 GUI 操作。构建机器本地 CPU 特性不应直接进入通用路由器发布目标。

分发压缩单独比较 gzip 等级、可选压缩格式与设备解压时间，维持安装器兼容。压缩包更小不意味着 RSS 更低。独立保存与二进制匹配的符号文件用于诊断，用户安装包无需携带全部符号。

官方语义参考：[Cargo profiles](https://doc.rust-lang.org/cargo/reference/profiles.html)，包括 opt-level、LTO、panic 与测试框架行为。

## 建议执行顺序与验收

| 顺序 | 实验 | 主要验收指标 | 约束 |
| --- | --- | --- | --- |
| 0 | 固定源码快照、工具链、目标与构建命令 | 可重建的原始/压缩体积、CPU/GiB、首字节、稳态/峰值 RSS | 不能拿现有不同时间产物推算收益 |
| 1 | 统计批量归并 | CPU/GiB、分配次数、计数完整性 | 取消与持久化语义必须覆盖 |
| 1 | TLS 默认 features 收窄 | 依赖图、链接产物、构建时间、协议连通 | 明确 provider 与后量子能力变化 |
| 2 | 池容量与 relay 缓冲分档 | P95 首字节、握手数、吞吐、空闲/峰值 RSS | 同时跑低并发和高并发场景 |
| 2 | 字体精简与 GUI 列表测量 | GUI 包体、启动耗时、交互耗时 | 三种语言与视觉回归 |
| 3 | 可选功能、索引、编译 profile、PGO | 逐目标完整对照表 | 仅在前项测量证明收益后扩大投入 |

每个实验使用独立产物，只改一组变量，并记录功能变化。当前没有性能加速比例或包体缩减比例的验证结果。
