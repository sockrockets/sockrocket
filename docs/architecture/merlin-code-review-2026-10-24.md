**1. [P1] 真实 IP 的 QUIC 可以绕过全局代理。**

位置：`merlin/scripts/iptables.sh`（审查时约第 811 行），IPv6 对应约第 389 行。

当 `--supports-udp` 返回失败时，脚本在通用 MARK 规则前插入“目标不属于 Fake-IP 网段、UDP/443 → RETURN”。该分支没有检查 `proxy_mode`，也没有限定中国 IP 或已经判定为 direct 的目的地。客户端使用 DoH、已有真实 IP 缓存或直接 IP 连接时，流量因此不进入 TUN，继续由固件处理；固件允许普通 WAN 转发时就会直连。全局模式也存在这一行为。在规则模式下，没有来源设备限定的 IP/端口规则同样可能被跳过；设备来源规则提前打标，不属于这个复现条件。

隔离复现：使用实际 CLI 解析 `proxy_mode: global`、VLESS `udp: false` 配置，将系统命令替换为记录桩，调用实际 `do_start`。生成顺序如下：

```text
-A SOCKROCKET_MANGLE -s 192.0.2.0/24 ! -d 198.18.0.0/16 -p udp --dport 443 -j RETURN
-A SOCKROCKET_MANGLE -s 192.0.2.0/24 -p udp -j MARK --set-mark 0x4765
```

建议让需要代理或拒绝的 UDP 进入核心，由核心按实际路由返回不可达以触发 TCP 回退。内核直连加速应只用于明确允许直连的流量。现有稳定性测试把所有真实地址 QUIC 的 RETURN 当作预期行为，需要补上全局模式和全局 IP 拒绝规则的反例。切换节点时还应核对 UDP 能力变化是否需要同步内核策略。

验证范围：已经确认实际生成的规则和顺序；没有在真实路由器上抓包。

**2. [P1] 高级配置保存校验比启动校验弱，会持久化无法启动的配置。**

位置：`crates/sockrocket-cli/src/cgi.rs`（审查时约第 754 行），对照 `crates/sockrocket-core/src/config/model.rs` 约第 119 行。

`act_save_config` 只执行 `serde_yaml::from_str::<AppConfig>`，绕过 `AppConfig::from_yaml_str` 中的节点组和规则目标校验，随后覆盖配置并在运行状态下重启。若规则引用不存在的节点组，保存阶段通过，启动阶段拒绝，正在运行的服务会被停止后无法正常恢复。

隔离复现：对临时配置提交 `target: group:missing`，实际 CGI 返回 `{"msg":"Config saved and validated","ok":true}`；随后同一二进制的 `--dump-rule-sources` 读取同一文件，以退出码 1 返回 `Rule refers to a missing proxy group`。没有启动真实代理。

建议保存前复用启动路径的语义校验，包含规则目标、活动节点索引、DNS 与运行模式组合等；校验失败不覆盖配置、不重启。对于只有实际启动才能发现的应用失败，保留上一份可用配置，并明确报告“已保存”和“已应用”的不同状态。补充“YAML 结构合法，但启动语义非法”的回归用例。

**3. [P2] 订阅下载持有配置锁，其他配置操作会超时。**

位置：`crates/sockrocket-cli/src/cgi.rs`（审查时约第 475 行和第 1037 行）。

`dispatch` 为 `add_sub` / `update_subs` 获取跨进程配置锁，并持有到下载、解析、保存和生命周期操作全部结束。后台任务最终仍调用该 dispatch。每个订阅的下载预算为 30 秒，而且多个订阅串行处理；其他写操作获取锁的预算只有 15 秒。后台化因此解决了页面等待，却没有解决配置操作互相阻塞。Stop 已被排除在配置锁外，这点已有正确处理。

隔离复现：回环 HTTP 服务暂缓返回订阅，实际 CGI 执行 `update_subs`，并发执行 `rename_sub`。重命名在 15.01 秒后返回 `Configuration transaction failed: Configuration transaction busy`；释放订阅响应后更新成功。

建议将过程分为“短锁读取快照 → 解锁下载 → 短锁重读并合并 → 解锁应用”。按订阅稳定身份合并，并在提交时丢弃已删除订阅的结果；共用层已有 `commit_subscription_refresh` 可复用。生命周期操作仍需遵守手动停止标记，但不应长期占用配置锁。

**4. [P2] 流量统计在异步转发路径同步全量落盘。**

位置：`crates/sockrocket-core/src/proxy/mod.rs`（审查时约第 452 行）、`crates/sockrocket-core/src/traffic.rs`（约第 540 行和第 572 行）。

网络 `poll_read` / `poll_write` 更新统计后，会沿 `record_parts → maybe_persist → flush` 同步序列化完整账本并写入配置目录下的 `traffic.yaml`。Merlin 默认目录位于 JFFS；原子写函数还写备份，并同步文件和目录。持续有流量时，10 秒保存间隔对应约 8,640 次全量保存/天，备份写入另计。该计算不是实机写入量或闪存寿命测量。

这会让执行该连接的异步工作线程等待存储 I/O。`last_persist` 的锁在落盘前释放，多个连接可能同时通过时间检查；没有统一的写入者负责快照顺序和 dirty 状态。低性能存储或并发传输时尤其值得优化，但本轮没有测量吞吐或延迟下降幅度。

建议数据路径只累积内存计数，由一个后台写入者合并快照，在阻塞线程执行落盘。根据允许丢失的统计窗口选定保存周期；页面实时统计可以走内存或 tmpfs，长期账本降低保存频率。关闭服务时做有界的最终 flush，用版本号保证较旧快照不覆盖较新快照。

**5. [P2] Fake-IP 持久化共用临时文件，并发保存会互相干扰。**

位置：`crates/sockrocket-core/src/dns/fakeip.rs`（审查时约第 225 行和第 234 行）。

多个 DNS 查询可以在保存间隔到期后同时进入 `persist`；间隔锁在真正保存前已经释放。所有写入者使用同一个 `fakeip.store.tmp`，一个写入者 rename 后，另一个会找不到临时文件；还存在旧快照替换较新快照、写入仍被其他写入者打开的 inode 等交错风险。仅加唯一临时文件名还不足以解决快照先后顺序。

隔离压力复现：链接当前核心库，对同一 Fake-IP 池进行 16 线程、480 次直接 `persist` 调用，两次运行均出现 2 次 `NotFound`。这是持久化方法的并发复现，不代表日常 DNS 请求的故障频率，也没有据此断言实机存储已损坏。

建议使用一个有序后台写入者，或至少为完整的快照/写入/提交过程串行化；配合独立临时文件和可靠原子替换。补充并发分配与保存、关闭时保存和重启恢复的一致性验证。Fake-IP 映射关系到客户端缓存地址在重启后能否继续使用，优先级高于一般代码整理。
