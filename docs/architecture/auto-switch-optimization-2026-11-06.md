# 全局自动切换优化（2026-11-06）

本轮修改工作区源码，未部署到路由器。线上仍为已验证的 0.0.18 定制构建；工作区标记为 0.0.16，不能直接将整个工作区构建覆盖线上。GPT 固定节点和路由器配置未更改。

## 行为

- 健康检查使用 HTTPS 443，验证目标证书，并要求完整 HTTP 响应头与 204 状态。gstatic 与 Cloudflare 两个目标错峰启动，共享 5 秒总期限，成功后取消剩余任务。普通界面 HTTP 测速保持原接口。
- 自动切换开启时，首次失败等待 2 秒后复查；复查成功清零失败计数，失败才计为一轮失败。现有 failure_threshold 仍按失败轮数生效。阈值为 1 时，最多约 12 秒完成故障确认，不必等待下一次 60 秒周期。
- 每轮从当前出站快照提取默认代理，绕过域名分流规则进行节点健康检查。手动热切换后的下一轮使用最新出站；在探测或候选筛选期间发生手动切换/配置刷新时，旧结果丢弃。提交时原子比较快照，避免检查与切换之间的竞态。
- 记录最多四个曾成功的活动节点。故障时先重新验证其中一条未避让的备用线路，成功即恢复；它不是预先测试过全部节点的备用池。
- 已确认失败的活动节点、复查失败的备用节点避让 120 秒。候选按连接指纹去重，避让同时覆盖同一连接的别名。避让不影响当前节点自身的后续健康检查，因此当前节点恢复时可自然恢复健康状态。
- 保留线上版本的候选轮换：最多四个并发探测、全量候选阶段 20 秒预算，下一轮继续轮换起点。加上最多一条备用节点探测，通常最多 25 秒，外层另设 30 秒硬期限和关闭取消。
- 不进行健康状态下的主动速度追逐，不迁移已有连接，不改变 GPT 等固定节点规则。

## 验证范围

新增覆盖：瞬时失败复查恢复、持续失败、正常请求无额外复查、手动切换不被过期故障结果覆盖、失败别名排除与候选去重、HTTP-only 隧道不能通过 HTTPS 健康检查且总期限受限。保留候选轮换、静默隧道超时、停止和订阅重启回归测试。

原始测试与编译日志：`.local/auto-switch-review/`。本轮没有进行路由器端 HTTPS 连通率、故障恢复时间或吞吐对照测量；代码测试通过不能替代线上网络验证。仍待后续优化：候选多轮评分、主动预验证备用池、GPT 固定线路独立健康策略。

验证结果：`cargo test -p sockrocket-core -p sockrocket-cli --lib --bins --offline` 共 692 通过、0 失败、9 忽略；`cargo check -p sockrocket-gui --offline` 通过；`git diff --check` 通过。依赖及已有未使用代码警告仍存在。
