## 本轮增补

1. **为备用探测目标保留执行时间。** 原循环给第一个目标整个剩余超时预算；目标无响应时，后面的备用目标没有机会执行。现在在共享测量期限内分配各目标预算。新增测试先复现旧代码超时失败，再验证主目标永远不完成连接时仍能通过备用目标。
2. **守护脚本使用多个出站目标。** 依次通过本机 HTTP 代理探测三个固定目标，每个最多 3 秒；要求预期的 204 响应。仅所有目标失败才计一次失败；连续三次仍然回退直连，恢复也必须有成功的实际响应。失败记录包含固定目标、curl 退出码、HTTP 状态和耗时，不记录节点凭据。新增测试覆盖主目标被阻断但备用可用、HTTP 错误、全部超时、禁止错误恢复及备用目标恢复 LAN。
3. **验证 firmware dnsmasq，而非仅相信重启命令返回值。** 日志中 dnsmasq 曾因配置错误退出，但控制脚本随后宣布 DNS 接管成功。现在通过已有 `--dns-health 53` 检查主 dnsmasq 的实际 DNS 响应，允许异步启动重试；失败时回滚 DNS 配置，并在安装 LAN DNS 重定向前退出。新增故障注入确认：即使重启命令返回成功，只要主 DNS 不应答，就不能宣布接管成功。
4. **减少配置生成阶段的误报。** 主配置暂时不存在/为空时等待重试；helper 的中间失败保留为调试信息，最终无法隔离的失败仍明确报错。
5. **让启停测试在 macOS 上真实执行。** 测试中的原地 sed 编辑改用 GNU/BSD 均支持的备份后缀；curl 使用固定应答的本地替身，避免测试意外访问真实网络。

DNS 应答验证证明服务可用，不能单独证明运行中的 dnsmasq 已重新读取所有主配置选项。上游 dnsmasq 文档明确说明 SIGHUP 不重读主配置；本轮未将配置文件状态或 HUP 本身当作完整的运行时配置证明。[dnsmasq 手册](https://thekelleys.org.uk/dnsmasq/docs/dnsmasq-man.html)

## 追加：TCP WARN 分类与计数

用户反馈 WARN 仍很多后，再次采集截至 07:05:54 的日志。其中 06:53:28 之后的 152 条 WARN 全是 `connection reset`。代码追踪到接收循环收到对端 RST 后返回 `ConnectionReset`，外层不区分 TCP 状态，全部记为 `task error` WARN。此记录说明该流被重置，不能直接认定代理服务崩溃，也不能单凭它判断每次重置的业务原因。

本次保持 TCP 错误传播、读写唤醒和连接回收行为，只调整诊断分类：

- 已建立/正在关闭的连接收到对端 RST：逐流 DEBUG，计入累计 `tcp_peer_resets`。
- 握手完成前收到对端 RST：仍为 WARN，同时计入 `tcp_handshake_resets`（它是总重置数的子集）。
- 非重置的 TCP 任务错误：保留 WARN，单独计入 `tcp_task_errors`。
- 重传耗尽、设备错误、容量告警等其他 WARN 不变。
- 三项匿名累计计数按每个 TUN 栈隔离，写入每分钟健康日志和现有诊断对象。计数随 TUN 栈重建归零；详细流日志仍可通过 DEBUG 排查。
