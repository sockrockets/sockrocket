分流

先选规则模式，再决定这条流量走哪。

分组建好以后不会自己接管流量。只有规则模式会看规则，并且规则的出口要写成这个分组或这个节点。

Routing

Choose rule mode, then choose where that traffic goes.

A group does not take over traffic by itself. Only rule mode reads rules, and a rule's exit has to name that group or that node.

三种模式

  • 规则：按分流规则决定出口。节点分组和「钉在某一个节点」只在这个模式里生效。
  • 全局：代理流量都走概览顶部当前选中的节点。
  • 直连：不走代理节点。

三种出口

出口跟着谁走
全局节点（规则里也叫「代理」）概览顶部当前节点。换顶部节点，这些规则一起换。
节点 · 名字只走这一个节点。换顶部节点时它不动。
分组 · 名字走这个节点分组。分组里换成员，不会改顶部的全局节点。

某一条规则要固定在一条线上，直接选「节点 · 名字」就够了。好几处规则要共用同一个出口、以后想一处改掉，再用手动分组。

节点分组

在节点页新建。它和分流规则里的规则分组不是一回事：规则分组是规则的文件夹，节点分组是出口。

  • 手动选择：只会使用选中的那一个节点，保存时也只保留这一个。
  • 备用：可以勾选多个，顺序就是尝试顺序。五分钟内从上次连上的成员开始；之后再从第一个开始。这个成员建连失败，就按顺序试剩下的。UDP 固定走第一个。已经建立的连接不会被搬走。
  • 测速：可以勾选多个。五分钟内沿用刚才更快的那个；过期后这些节点一起比握手。顺序不决定用哪一个。

成员失效不会悄悄改走全局节点。分组里切换成员，也不改变顶部当前节点。

让分组生效

  1. 概览里选择规则。
  2. 在节点页建好分组。
  3. 打开分流规则。把这一组规则的分组出口选成「分组 · 名字」，或在单条规则的处理方式里选同一个分组。

分组出口会改掉原来走代理、节点或分组的规则。这一组里的直连和拒绝保持不变。

预设、设备与去向检查

  • 常用预设：AI 服务、海外视频、Telegram 网页、开发工具、Apple 直连、Microsoft 直连、国内站点。添加后是停用的，再由你打开。它们覆盖常见域名，不是这些服务的全部地址；Telegram 数据中心的 IP 仍按 IP 规则或兜底走。
  • 设备兜底：给一台设备或一个网段单独的最终出口。没单独设置的设备继续用全部设备的规则。请给设备固定 DHCP 地址。选「继承全局」会删掉这个来源的最终规则，目的域名和 IP 例外还在。
  • 去向检查：输入网站，看命中哪一条、为什么、走哪个出口。不修改规则，不发起代理连接，也不保存查询记录。

匹配顺序是：这台设备的目的规则 → 全部设备的目的规则 → 国内直连 → 这台设备的兜底，否则全局兜底。

Three modes

  • Rule: rules choose the exit. Node groups and a pinned node apply only here.
  • Global: proxied traffic uses the node selected at the top of the overview.
  • Direct: no proxy node.

Three exits

ExitWhat it follows
Global node (also labeled Proxy)The overview's current node. Changing it moves every rule that uses this exit.
Node · nameThat node only. The overview selection does not move it.
Group · nameThat node group. Changing a member does not change the global node.

Pin a node when one rule should stay on that line. Use a manual group when several rules should share one exit you can change in one place.

Node groups

Create one on the Nodes page. A rule group on the Routing page is a folder of rules. A node group is an exit.

  • Manual: one node. Saving keeps only that node.
  • Fallback: several nodes, in list order. For five minutes, new TCP starts at the last member that connected, then it starts at the first again. If that member fails to connect, the rest are tried in order. UDP stays on the first. An open connection is not moved.
  • URL test: several nodes. For five minutes, new TCP reuses the fastest recent handshake. After that the members race, and order does not choose the winner.

A missing member is not replaced by the global node.

Use a group

  1. On the overview, choose Rule.
  2. Create the group on the Nodes page.
  3. On Routing rules, set that rule group's exit to Group · name, or set one rule's action to the same group.

The rule-group exit rewrites rules that were already using a proxy, a node, or a group. Direct and reject rules in that folder stay as they are.

Presets, devices and the routing check

  • Presets: AI services, overseas video, Telegram web, developer tools, Apple direct, Microsoft direct and domestic sites. They are added disabled. The lists are common domains, not every endpoint. Telegram data-center IPs still follow IP rules or the final rule.
  • Device default: a final exit for one device or prefix. Devices without one keep the shared rules. Use a DHCP reservation. Inherit removes that source's final rule and leaves destination exceptions.
  • Routing check: enter a site and see which rule matched and which exit it uses. It does not change rules, open a proxy connection, or store the query.

Order: this device's destination rules → shared destination rules → domestic direct → this device's final, otherwise the global final.
