# Merlin 稳定性审查与修复

本轮针对“全网断网或 DNS 失效”审查服务脚本、dnsmasq 接管、TUN/策略路由、守护恢复、DNS 查询并发和 Web API。结论是有多处会放大故障、错误恢复或资源占用的缺陷；下表列出的 21 项缺陷已完成本地修复，关键路径有故障注入和回归验证；仍有独立问题列在文末，尚未完成全部审查范围。尚未部署并开启代理做真机验证。

## 路由器只读检查

使用项目既有连接配置通过 SSH 读取状态，未上传文件、重启或改变网络。检查日期为 2026-10-15：

- ARM64，内存约 995 MiB，可用约 512 MiB；JFFS 使用约 22%。采样时没有观察到持续内存耗尽。
- `stopped` 标记存在；代理主进程未运行，API 进程独立运行。
- dnsmasq 正在本机/网关的 UDP 53 监听；未观察到 Sockrocket UDP 5300 或其专用策略路由处于启用状态。没有主动发送 DNS/代理请求，不能据此断言所有客户端联网均正常。
- API 的 `/proc/<pid>/fd/1` 与 `fd/2` 均指向 `sockrocket.log (deleted)`。这直接印证了日志轮转替换 inode 的问题：当前可见日志不再接收该进程输出，旧文件仍被描述符持有。
- 可见日志中未匹配到 panic、half-dead、内存压力等历史分类，但由于描述符已经指向删除文件，**这些计数不能排除历史故障**，也无法据此还原此前断网的唯一根因。

## 已修复问题

| 优先级 | 缺陷与触发条件 | 修改 |
| --- | --- | --- |
| P1 | dnsmasq 加载插件片段失败后，新片段仍留在配置目录；固件 DNS 可能无法启动 | 回滚片段、撤销上游 pin，再尝试恢复固件 dnsmasq；返回失败，不再假报成功 |
| P1 | DNS 监听消失时，仅移除片段，没有撤销已写入的 `127.0.0.1#5300` pin | 统一走 DNS 清理流程，恢复原上游 |
| P1 | 降级启动强制以 SOCKS-only 启动，恢复逻辑又只检查 TUN 是否存在；未恢复也清除降级标记 | 降级时仍按用户意图创建 TUN，但不接管 LAN；TUN、路由或 DNS 未就绪时保留降级标记与直连状态 |
| P1 | 看门狗因内存压力退出代理，快速 guard 随后又立即恢复接管 | 85% 降级、低于 80% 才恢复；兼容无 MemAvailable 的旧内核，计算移至 awk 避免 32 位溢出 |
| P1 | 异步 FAST_START 在无锁后台等待 TUN/DNS，可能在用户停止后重新装回规则 | 后台初始化独立持锁，重新检查停止、降级、节点和进程状态；后台守护不继承主进程锁所有权 |
| P1 | 防火墙重建钩子绕过降级/停止状态，重新接管 LAN | 新增带锁 `firewall-restore` 入口，安装钩子统一经过状态检查 |
| P1 | 先向 PREROUTING 挂 MARK，再建路由；关键命令失败被忽略 | 先准备路由、策略与转发规则，再暴露 MARK 链；必需规则失败时移除接管链并返回失败 |
| P1 | 每次重建重复 `ip rule add` | 检查专用 fwmark/table 规则，重复调用不新增同一条规则 |
| P1 | UDP DNS 对每个包无限 spawn；慢上游或突发查询可积累任务 | 前台最多 128 个任务，超额返回 SERVFAIL；过期缓存后台刷新最多 16 个，不无限排队 |
| P1 | API 的信号量在任务内部等待；只限制了执行，没有限制排队任务与 socket | 接收后先申请六个配额之一，过载立即关闭额外连接 |
| P2 | 日志轮转 rename 替换文件，长期运行进程继续写删除 inode | 原 inode 内限长，已有写入描述符继续写可见文件；真机已观察到旧版本这一缺陷 |
| P2 | 重复 fail-open 即使没有配置变化也重启 dnsmasq | 清理幂等化，无片段或 pin 变化时不重复重启 DNS |
| P2 | 脚本启动、DNS 开关、恢复等操作被 `release_lock` / `|| true` 掩盖失败状态 | 增加保留真实返回码的锁包装，关键操作正确返回失败 |
| P2 | HTTP 出站健康探测把代理 HTTP 502 当作 curl 成功 | 使用 `curl -f`，HTTP 错误不再触发成功恢复 |
| P2 | DNS 关闭后查询子任务仍持有 socket，早到的关闭通知还可能丢失 | JoinSet 跟踪并取消查询任务，释放监听端口；CLI 使用可保存通知的 notify_one |

| P1 | 常规/快速启动中 TUN 等待超时或防火墙安装失败，仍继续安装 fake-IP DNS；客户端拿到地址却无可用路由 | 统一启动网络事务，先确认 TUN 与转发，再接管 DNS；失败进入直连降级，保留恢复守护 |
| P1 | DNS NAT 创建/添加规则失败被最后的成功日志掩盖；dnsmasq 接管路径也忽略 helper 失败 | 每条必需规则检查返回码；失败清理部分 NAT，撤销 DNS 片段与上游 pin |
| P1 | DNS 监听任务退出/绑定失败只输出警告，主进程继续存活，监督进程无法察觉半失效 | DNS 异常退出通知主循环统一关闭服务，使监督进程能够重启恢复 |
| P2 | DNS 去重表只在正常返回时清理，取消请求遗留条目；旧等待者可能删除新请求条目 | 使用可在取消时执行的 RAII 清理；仅最后一个调用者移除自己对应的共享条目 |
| P2 | API 在发现头终止符后跳过 16 KiB 检查，重复/非法 Content-Length 和 Transfer-Encoding 可造成模糊请求解析 | 严格校验长度、请求行和 UTF-8；拒绝重复长度与不支持的分块传输 |
| P1 | TUN 返回方向 ACCEPT 初次检查通过后，在重排时删除，再插入失败仍继续安装 MARK | 检查最终插入返回码，失败撤销接管并返回错误 |

保留了工作区原有的 Fake-IP/QUIC 修改；本轮没有覆盖用户已有 GUI 或设计改动。

## 验证

- `cargo test -p sockrocket-core -p sockrocket-cli --offline`：**360 项通过**（core 328，CLI 32）；需要外部服务的测试按原配置跳过。
- `sh tests/integration/merlin_stability_test.sh`：**15 个场景通过**。覆盖 启动 TUN/路由失败阻止 DNS 接管、DNS NAT 规则失败清理及上游回滚、DNS 重启失败回滚、重复清理、监听消失恢复上游、缺 TUN/路由失败保持直连、内存恢复阈值、旧内核内存计算、日志写入描述符、降级启动、命令返回码、防火墙事件和策略规则幂等。
- DNS 负载测试使用本地不回应的上游，验证超额请求及时失败、关闭取消在途任务和端口释放；API 使用六个未完成请求验证第七个连接不排队，释放配额后可以继续服务。
- Shell 语法与 `git diff --check` 通过。故障注入检查已加入 Linux CI。
- ARM64 musl release 构建完成，产物为静态链接 ELF。构建使用仓库 Zig 包装，并为顶层二进制设置 `-C link-self-contained=no`，避免 Rust/Zig 重复提供 CRT。
- **未做**真机启用/重启、故障注入、长时间高负载、WAN 切换、IPv6 或各机型固件矩阵验证。

## 部署边界

本地修复集合位于 `dist/merlin-stability-aarch64-20261015/`，包含二进制、两个运行脚本、安装钩子参考和校验信息。它是**修复集合，不是软件中心离线安装包**，不要直接运行其中的安装参考脚本。

正式部署需先备份二进制、脚本与现有钩子，保留用户配置和手动停止意图；替换后更新 `firewall-start` 中 Sockrocket 自己的钩子块，不覆盖其他插件内容。API 应重新启动以关闭已删除日志描述符。开启代理会改变 DNS/路由，必须另行确认操作窗口，然后执行域名解析、HTTP/SOCKS 与 LAN 实机验证，失败立即退回直连。
