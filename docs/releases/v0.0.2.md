# v0.0.2

## Merlin routing and subscriptions

- Add per-device IPv4 address/subnet routing in the integrated router UI, alongside destination rules and explicit priorities. Device final rules apply before global rules; unsupported source policies fail safely before transparent interception is attached.
- Add a flow overview derived from effective rule order and the current routing mode, with a local device-address preview.
- Add an Exit proxy button on every plugin page. Preserve saved subscriptions and rules during cleanup.
- Run WebUI subscription imports and updates as background jobs with progress, refresh recovery and duplicate-launch detection. A failed source retains its previous nodes; completing an update preserves a manual Stop.
- Accept explicit Base64 imports and URL-safe Base64 subscriptions; report skipped URI entries without logging credentials.

## Protocol compatibility and reliability

- Implement native VLESS Vision over TLS 1.3 or REALITY/TCP, including XUDP for non-443 UDP. Fix half-close flushing when only the downlink has switched to direct copying, preventing pending TLS ciphertext from being discarded.
- Support Hysteria2 and AnyTLS leaf-certificate SHA-256 pins, including with insecure mode enabled. Preserve trust settings across saves, share links, deduplication and Clash import/export.
- Support Hysteria2 ALPN, upload/download bandwidth settings and Fast Open. Accept numeric, decimal and unit-suffixed bandwidth values. Share upload credit across TCP/UDP and return unused credit after short writes or cancellation.
- Reject unimplemented sing-box TLS security constraints rather than silently weakening authentication. SPKI public-key pins and custom trust/client-certificate constraints are not yet implemented.

## Validation and limits

- 539 core/CLI regression tests passed; 15 live/manual tests are skipped by default. Independent sing-box Vision and Chrome-profile Hysteria2 TCP/UDP interoperability tests were also run successfully. QUIC wire-capture, Retry, certificate/pin verification and repeated key-update checks passed.
- 24 Merlin fault-injection scenarios and 63 service-lifecycle assertions passed. Frontend rules, RPC and background-job checks passed.
- Production core/CLI Clippy, desktop GUI compilation checks and ARM64 musl release compilation passed locally.
- Private subscription URLs, credentials, node endpoints and local diagnostics are excluded from the published source and packages. GitHub Actions performs the release builds after this tag is pushed.
- Local simulation does not replace long-running device validation. Vision over WebSocket, gRPC/XHTTP, Hysteria2 obfuscation and port hopping remain unsupported; see the [protocol guide](../protocols.md).

## Subscription startup fix

- Clear inherited HTTP content lengths in the software-center bridge before forwarding JSON to CGI.
- Recover the exact client request ID after a lost launch response; repeated IDs return the existing job result.
- Preserve original startup errors, failed stages, OS error codes and troubleshooting suggestions. Add a persistent, copyable diagnostic report containing only allowlisted metadata.
- Remove private request files when startup fails and retain existing subscriptions and nodes.
- Encode software-center request bodies as UTF-8 Base64 so firmware field escaping cannot corrupt JSON, Chinese names or quoted rule content. Decode with strict size limits in CGI; retain the legacy raw request path.
- Return safe request parsing/encoding errors and backend process exit codes instead of a generic service-status error. Diagnostic reports exclude request bodies, subscription credentials and raw stderr.
- Install the full software-center package with atomic binary replacement, restart the API on the new binary and preserve a manual Stop. Existing configuration is retained.

## Hysteria2 subscription compatibility

- Accept recognized browser fingerprint hints (`fp=chrome`, etc.) appended by generic subscription exporters. Apply the native Rust Chrome 115 baseline QUIC handshake profile for `chrome`/`chrome115` with ALPN `h3`; other recognized browser hints remain metadata with an explicit compatibility note. The baseline does not reproduce ALPS, Chrome Initial packet numbering/framing or HTTP/3 request behavior. Certificate verification, certificate pins and unsupported security constraints remain enforced.
- Report duplicate subscriptions explicitly and explain older saved duplicate/empty-import failures with actionable diagnostics.
- Mark subscription URLs as required and names/formats as optional. Validate new URLs before saving; skip failed sources during batch updates while retaining their previous nodes. Separate informational compatibility notes from actual import failures.
