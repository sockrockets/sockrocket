# v0.0.19

> Offline installation compatibility: the initial v0.0.19 archives omitted
> `webs/Module_sockrocket.asp`, which Software Center requires before running
> the installer. This rebuild restores that regular file alongside
> `webui/sockrocket.asp`; removing only the duplicate executable retains nearly
> all packaging savings. Download the rebuilt archive and its matching checksums.

## Smaller Merlin installation packages

- Ship one executable per platform package and preserve both Web UI paths required by the installer and Software Center. The installer still publishes the required firmware pages, and standalone binary download names remain unchanged.
- Local comparisons with identical executable inputs reduced the ARM64 package from 12.67 MiB to 6.43 MiB and ARMv7 from 12.53 MiB to 6.36 MiB, approximately 49%. These are packaging comparison samples, not guaranteed sizes for every v0.0.19 release asset.
- Reduce download and temporary extraction space without changing the executable, enabled protocols or runtime performance. Installed executable size and runtime memory are not halved by package deduplication.
- Keep regular archive files rather than links, preserving the online updater's archive checks. Add coverage for all seven platform packages, architecture selection, executable contents and release checksums.

## Update download recovery

- Retry failed package downloads through the running local SOCKS proxy, including remote hostname resolution, while retaining TLS verification. Successful normal downloads do not use the fallback.
- Show the error chain while removing download URLs from network errors. Failed network attempts preserve the destination file.
- Five update tests passed, covering fallback routing, direct success and error privacy; CLI Clippy checks passed.

## Runtime performance and reliability

- Improve GeoIP lookup and routing cache handling, batch traffic accounting, and move Fake-IP persistence work out of the request path.
- Improve connection pool lifecycle and TLS connection reuse, including VLESS handshake flushing.
- Recheck transient health failures before failover, reject stale probe results after configuration or node changes, and bound candidate probing.

## Validation

- Packaging tests cover all seven platform mappings; installer regression and 11 updater scenarios passed locally.
- A compact package using an existing 0.0.18 executable was installed on an ARM64 Merlin router to validate the packaging change. Configuration and executable hashes were preserved; the API, DNS, proxy access and installed Web UI passed checks. This was a packaging validation, not a deployment of the final v0.0.19 build.
- Workspace and Merlin versions are synchronized to 0.0.19. Full release binaries are built and validated by the tag-triggered workflow.
