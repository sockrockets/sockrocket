# v0.0.3

## Merlin routing and optional presets

- Replace the limited flow overview with a routing explanation covering every rule phase. Check a destination, optional source-device IP and port using the core matcher; see matching conditions, the winning rule and the configured proxy/direct/reject outcome.
- Open the exact matching rule for inspection or editing, or filter the full list by a diagram stage. Rule indices remain correct across priority sorting, disabled entries and device/global phases.
- Mark unresolved IP/GeoIP conditions as provisional. Input, configuration, mode, service-state and exit changes invalidate stale results. Queries do not save history or open proxy connections; this explains saved policy rather than testing website reachability.
- Add seven optional groups containing 79 domain rules: AI services, overseas video, Telegram web, developer tools, Apple direct, Microsoft direct and domestic sites. Preview their contents, import disabled rules, then explicitly enable a group.
- Preserve existing matching selectors, priorities, enabled states and user edits during repeated imports. Disabled imports do not restart the proxy. Group toggles validate state values and edit snapshots; unchanged toggles avoid configuration writes.

## Software Center lifecycle

- Make Exit return to Software Center without stopping the proxy. Stop remains available separately on the Overview page.
- Keep fresh installations stopped until explicitly started. Preserve saved Stop across startup and installation retries, and retain existing configuration and upgrade intent.
- Report Software Center enablement from the running proxy rather than the installed marker or independent management API. Install and remove the firmware status callback with the complete package.

## Validation and scope

- Core/CLI regression coverage: 548 passing tests; 15 live/manual tests remain ignored by default. Frontend checks cover routing results, preset activation, stale responses, software-center transport and subscription jobs.
- Merlin lifecycle and installation coverage includes 26 fault-injection scenarios and 63 lifecycle assertions. Production core/CLI Clippy and ARM64 musl release compilation passed locally.
- Make the API admission test validate complete HTTP response framing instead of relying on EOF, so a Windows connection reset after a complete response does not fail the test. Truncated or incorrect responses still fail validation.
- UI checks use synthetic data. Private subscription URLs, credentials, node endpoints, personal build paths and local diagnostics are excluded from the release package; test code is not packaged.
- Upgrade through Software Center using the complete package. Existing settings and manual Stop are retained. Presets contain common domain selectors, not exhaustive service endpoint lists; Telegram data-center IP traffic still follows IP rules or the default route.
