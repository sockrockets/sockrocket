# 竞品调研与产品设计决策

调研日期：2026-10-15。方法：阅读产品官方文档、官方项目说明，对照 Sockrocket 本地代码；未安装竞品实测，也未依据第三方“官网”或下载站判断功能。以下将文档事实与本项目设计判断分开。

## 结论

Sockrocket 应定位为“日常连接足够简单，出问题时能够解释”的原生代理客户端。保留 macOS 设置的分组列表，让连接状态、流量接管、路由模式和出口形成一条清楚的操作链。高级能力应有完整入口，但不占用首页的主要注意力。

## 官方资料对照

| 产品 | 已核实的事实 | 对 Sockrocket 的启发与取舍 |
| --- | --- | --- |
| Clash Verge Rev | 官方项目列有配置增强（Merge / Script）、系统代理与 TUN、可视化节点和规则编辑。[项目说明](https://github.com/clash-verge-rev/clash-verge-rev) | 可视化与文本编辑应互通。Sockrocket 先把单条编辑、批量预览和生效范围做清楚；不把尚未支持的脚本增强、WebDAV 等塞进界面。 |

| Hiddify | 官方教程提供剪贴板/手动导入、首页连接、配置切换、节点延迟与排序，并把高级设置单独组织。[使用教程](https://hiddify.com/app/How-to-use-Hiddify-app/) | 首次使用应围绕导入、选节点、连接三个动作；名称搜索、来源筛选与排序是管理工具，不要求用户先理解网络细节。 |
| sing-box Apple 客户端 | 文档区分 Apple 平台服务与 TUN 的实现，并明确进程等规则字段存在平台限制。[功能说明](https://sing-box.sagernet.org/clients/apple/features/) | 能力要由平台与内核决定。不能因为竞品能显示某个字段，就在 Sockrocket 中展示不存在的进程信息或声称已有 NetworkExtension。 |

上述是公开文档调研，不是性能、易用性评分或市场占有率比较。各产品的版本和平台差异不能用一张“全支持”表抹平。

## 这版原型存在的问题与改进

| 问题 | 用户可能形成的误解 | 本轮落地 |
| --- | --- | --- |
| 首页只有“已连接” | 以为服务启动就代表所有应用走代理、目标网站可访问 | 区分服务运行、系统代理/TUN接管、目标连通性；未验证明确显示，未接管时提供修复入口 |
| 延迟值缺乏上下文 | 把单次低延迟当成高带宽或长期可靠性 | 首页读当前实际选中项；节点显示来源、测试时间、未测速状态，说明延迟含义 |
| 节点数量与来源展示虚数 | 不清楚订阅和导入节点的关系 | 来源统计由示例条目计算；搜索、来源、收藏、排序可组合使用 |
| 策略组只列名字 | 不理解自动选择与故障切换为什么选不同节点 | 明确策略类型、当前出口、成员数与选择依据；仅开放现有三类策略 |
| 规则改错后难以恢复 | 不敢使用批量覆盖或排序 | 对有效规则修改保存一份内存快照，提供最近一次撤销；批量仍先预览再确认 |
| 诊断只有成功提示 | 无法区分监听、接管、节点、DNS/目标问题 | 增加四步诊断面板，逐项展示已知状态；所有模拟结果明确标识 |
| 网络参数取消时回到硬编码默认值 | 丢失之前真正保存的配置 | 原型保留最近应用值，放弃草稿时恢复该值 |
| 页面缺少密度与层级 | 用户看不到常用功能，列表像长表单 | 首页用紧凑状态路径与三项指标；管理页用统一工具栏、选中态、辅助元信息、安静提示 |

## 完整性与能力边界

### 现在能够对齐的能力

- `config/group.rs`：手动组、URL 测速、故障切换的节点成员解析与选择。文档和原型按这些真实行为设计，不增加 Smart、负载均衡、嵌套组的假入口。
- `config/model.rs`：订阅、节点、传输、TLS、规则和组的字段。正式界面应从模型生成对应协议的必要字段，而不是通用“密码”框代替所有协议。
- `config/watch.rs`：配置更新区分可重载字段与需要重启监听的字段，解析失败保留旧配置。设计上的“应用更改”和错误反馈应接这一状态。
- `proxy/mod.rs` 的 `ConnectionRecord`：目标、入口协议、开始时间、关闭后字节数与状态。当前没有进程归属和完整命中链，界面不伪装已经采集。

### 应在实现前补齐的流程

1. **导入**：真实解析结果、同源更新、去重、节点移除对策略组的影响、失败不替换旧配置。原型的格式识别与数量仍是演示，不能作为生产解析器。
2. **引用完整性**：策略组改名/删除时，规则引用必须同步迁移或阻止删除；订阅更新移除成员时，显示失效成员并可修复。
3. **连接恢复**：断开与启动失败恢复用户原系统代理；TUN 的拒绝、失败和关闭分开反馈；服务状态不等同于真实网站验证结果。
4. **规则解释**：测试匹配须调用真实路由引擎，特别是 DNS、GeoIP、缓存和默认规则。现有原型仍仅演示测试界面，不作为实际路由结论。
5. **分享与诊断**：用真实模型生成 URI 与二维码；日志导出提供字段脱敏选项。未接入前不制作可扫描但无效的二维码。
6. **状态持久化**：偏好与规则经真实配置保存、写入失败可重试；原型在内存中演示，刷新恢复默认，撤销仅限本次会话最近一次规则操作。

## UI 规范与验证口径

继续使用 macOS 系统字体、细分隔线、单一系统蓝选中、灰色分组背景。增加深浅色下的语义颜色、控件焦点、可点击区域和窄窗口布局。主页的路径是状态解释，不是实际网络拓扑监控。

已有规则检查继续保留，并新增节点过滤/收藏/排序、服务与接管状态差异、撤销、配置取消恢复与诊断入口的脚本验证。静态 SVG 会同步更新并渲染检查。本地浏览器曾拒绝 `file://` 访问，本轮不绕过该限制；脚本状态检查和静态设计图检查不等同于浏览器端到端验证。
