# TUN 启动 MTU 选择

CLI 和桌面端在安装 TUN 路由之前选择 MTU，将同一个值用于网卡、ipstack 和 TCP MSS（MTU − 60，兼容 IPv6）。运行中的连接不修改 MTU；切换节点、重新拨号或换网络后，需要重新启动 TUN 才会重新选择。

配置未填写 `tun_mtu` 或设置为 `null` 时自动选择。手动覆盖示例：

```yaml
tun_mtu: 1400
```

手动范围为 1280–9000；非法值会报错，不能静默修改。桌面端会保留此配置，修改后重新启动 TUN 生效。

## 自动模式

1. 根据当前节点解析得到的 IP，查询到该 IP 的实际出口路由和网卡 MTU，而非只读取默认网关。Linux 使用 `ip route get` 和 sysfs；macOS 使用 `route get` 和 `ifconfig`。
2. 对节点 IP 去重，在总预算内处理最多 32 条路径，先复用已保存结果；需要探测时发送禁止分片的 ICMP 包，先验证出口上限，明确过大时再从 1280 起搜索可通过的包大小。仅明确的“包太大”反馈可以缩小探测范围。Linux 路由查询明确返回 `Network is unreachable` 的地址不会被出口使用，因此跳过；普通超时、缺少工具、解析失败或节点不回应均不能据此跳过，仍保守处理。
   Merlin 的 BusyBox ping 可能不显示已收到的“需要分片”错误。探测不明确时会重新查询内核路径 MTU；只有内核明确给出了更小的值，并且该大小的 DF 探测成功，才接受结果。不会仅凭超时推断较小的 MTU。
3. 从外部路径参考值中预留保守余量：一般为 80 字节，Hysteria2/TUIC 为 100 字节，开启 UDP 的 Shadowsocks 为 128 字节。这是兼容性策略，**不是代理封装开销的精确公式**。自动模式的 TUN 值在 1280–1500 内，WireGuard 还会参考节点自身 MTU。
4. 没有可靠探测结果时，选择出口参考值减余量与 1400 中的较小值，并保持不低于 1280。无法读取出口时回退 1400。不支持出口读取的平台（目前为 Windows）、macOS 的 IPv6 探测，以及缺少完整 ping 工具的路由器都会保守回退。
5. 探测和路由查询共享 6 秒预算，每个外部命令最多 1200 毫秒；超时子进程会被终止并回收。此预算不包含调用方的节点 DNS 解析或磁盘缓存写入。Linux 参数兼容 Merlin 自带 BusyBox ping，不使用其不支持的 `-n`。

成功的外部路径测量自动保存在配置目录的 `tun-mtu.json`，最多保存 32 条节点路径结果。缓存按节点地址、协议、端口、目标 IP、出口网络及余量区分。**相同节点和网络下直接复用，不定期过期，也不在每次启动时发送探测包。** 更换可识别的出口网络、节点配置、缓存损坏、内核报告更小路径 MTU，或手动删除缓存文件后，才重新探测。普通兜底值不作为成功测量保存；缓存不可写不阻止启动。
Linux 的网络标识包含出口接口、接口 MTU、网关、源地址和路由表，不包含会持续变化的路径缓存剩余秒数。
这是自动结果，不会写入代表手动覆盖的 `tun_mtu`。如远端路径变化但本地网络标识未变，软件无法仅靠本地信息识别；出现疑似 MTU 故障时，删除 `tun-mtu.json` 并重启 TUN 可重新测量。

## 能解决的范围

外部 ICMP 探测只提供节点路径的 MTU 参考，无法验证实际代理协议、所有 DNS 地址、策略路由、局域网回程和 UDP 大包的完整行为。TCP 代理会重新分段，QUIC 也有自己的外部路径处理，所以不能把 TUN MTU 与 WAN MTU 简单等同。多个节点组切换后的路径也不由当前节点的一次探测证明。

日志分别记录出口 MTU、外部路径探测结果（未知时为空）、预留余量和最终 MTU，不能将该日志当作端到端代理正常的证明。自动选择旨在减少手动配置，不能保证所有网络故障消失。发布前仍需在真实路由器验证 PPPoE、IPv6、不同节点、大 TCP 下载及 UDP 场景。
